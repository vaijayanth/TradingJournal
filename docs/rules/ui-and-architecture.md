# Ui and architecture (rules split out of CLAUDE.md on 2026-11-25)

> Verbatim dated notes, original order. Read this file when the task touches: index.html, page behaviour, WORKSPACES registry. Dated notes here still override older ones; CLAUDE.md core rules win on conflicts.


Fundamental rebuild driven by the user's mockups (dashboard.html / performance.html / analysis.html; Live, Strategy, Journal, Config mockups not yet received). **Done page by page, user go-ahead after each step**, in this order: Step 0 foundation → Live Trading → Dashboard → Performance → Analysis → Strategy/Journal/Config. Keep each page visually close to its mockup.

- **Workspaces = brokers** (DHAN / ZERODHA / ICICI switcher in the header, persisted in `localStorage 'tj_workspace'`). Registry + gating live in the `WORKSPACES` / `WS` block just above `showPage()` in index.html (`wsSelect`, `wsGate`, `wsApply`, `wsInit`). `pages:{}` per workspace = which pages have real data today; pages without data show a "Not available for this workspace yet" placeholder (`#ws-empty`) and their nav tab is dimmed. **When a page gets a workspace adapter, flip its flag in `WORKSPACES`.**
- **Common pages, broker-agnostic.** Dashboard / Performance / Analysis / Live render from a normalised data contract (documented in the comment above `WORKSPACES`), never from a broker directly. Strategy rules and health thresholds belong to the workspace config (dh252 ≠ SST: target WR ≥70% vs dh252 backtest ~42%), not hardcoded in pages — the existing pages still hardcode SST thresholds until they are migrated.
- **MCP data path:** browsers cannot call MCP. A Claude session (later a scheduled job) pulls broker data over MCP and commits a snapshot JSON the adapter reads (Dhan: `dhan-live/dhan_live_signals.json`). **Zerodha currently = the legacy Google Sheet feed (TRADES sheet, SST)** — user confirmed; it is to be swapped for an MCP snapshot later. ICICI: not connected.
- **Default workspace is Zerodha** during the transition (the existing sheet-backed Dashboard/Performance/Analysis keep working). Flip the default to Dhan when Dhan's Dashboard lands.
- **F&O** stays as a Swing/F&O mode chip (right side of the nav row, reusing `switchStrategy`) — no new F&O pages; fresh logic for all three brokers later.
- Header is now `.app-header` (topbar: brand · broker switcher · status; nav row below). The nav tab for `page-dhanlive` is labelled "Live Trading" (page id unchanged). The mockup's Dashboard figures (225 trades / 94.7% WR / 183 open) are the **Zerodha sheet** numbers, not Dhan's — Dhan's trade log has 0 closed trades so far.
- Mockup copy to NOT carry over: the Analysis mockup's diagnostics are SST-hostile ("review exit rules letting losses persist", "positions stop out", "₹2,000 tier", partial exits flagged red) — rewrite them to each strategy's own rules. Keep the app's blue accent for active states (the Performance/Analysis mockups use green, which is reserved for profit).
- **Step 1 done (Live Trading):** the Live page no longer reads `dhan_live_signals.json` directly. `WS_ADAPTERS.dhan` → `wsNormalizeDhan()` converts the engine output to the common contract (`meta/capital/positions/signals/rules`), `wsLoad(id)` caches it in `WS.data[id]`, and `dhLive*` render from that. The engine now also writes a `rules` block (add trigger / fraction / cooldown) that the page displays instead of hardcoding. Internal function/ID names still use the `dh*`/`dh-live-*` prefix (kept to avoid churn) even though the page is the generic "Live Trading".
- **Step 2 done (Dhan Dashboard):** new contract-driven `#page-dashboard2` (CSS prefix `d2-`, JS `d2Render`/`d2Ensure`/`d2Attn`), shown instead of the legacy sheet dashboard for workspaces with `pages.dashboard === 'v2'` (`WS_ALT` + `wsGate`). Zerodha still uses the legacy `#page-dashboard`. Default workspace is now **Dhan**. Header ↻ calls `wsRefresh()` (reloads the active workspace's snapshot, falls back to the sheet `refreshData()` for Zerodha). Dhan basis decisions (user, 2026-11-08, **revised after the first equity curve was judged wrong**): the dh252 capital base is a **fixed ₹20,00,000 (`initial_capital` in `dh252_trade_log.json`); later deposits are deliberately ignored**. Equity curve = 20L + realised + unrealised P&L day by day (flow-neutral — never plot cumulative capital deployed, that just rises with every buy/deposit). The engine builds it (`equity_curve` in the signals JSON) from `data/dh252_daily_closes.json`, produced by `scripts/build_dh252_daily_closes.py` (yfinance daily closes for the 48 symbols; re-run it before the engine each refresh). Approximation: current qty/WAC are used from the entry date (the 2 positions with add-ons treat the add as day-one). KPIs: Starting capital / Realised P&L FY / Unrealised MTM / FY return (÷20L) / Portfolio value (= 20L + P&L); 'Return on deployed' lives in Portfolio health. **Closed-trade metrics show an empty state** (Dhan MCP tradebook is today-only; `closed: []`) until exits are recorded — Re-entry queue works the same way. "Below 200 SMA" comes from the engine: `compute_dh252_live_signals.py --ohlc-dir <dir of <SYMBOL>_NS.parquet from backtester's backfill-checkpoints branch>` adds `sma200/sma50/sma_asof` per position (the cache currently ends 2026-10-19, so the UI footnotes the as-of date). Re-run command now needs `--ohlc-dir`.
- **Step 3 done (Dhan Performance):** contract-driven `#page-performance2` (`p2*` JS / `p2-*` ids; `WS_ALT` now maps legacy page → `{el, fn}`), shown for `pages.performance === 'v2'`. Sections per mockup: KPI strip (Net P&L FY = realised + open MTM, Return on ₹20L, Realised, Max drawdown on the daily equity curve, Closed trades), equity curve (shared `d2CurveSvg(d, uid)`), monthly returns, trade quality (closed-only → empty state), workspace comparison (only the active workspace has contract data; others show '—'), top contributors/detractors (open-position P&L until exits exist), P&L calendar (daily Δ of total P&L, month nav), quarterly/annual summary. Everything derives from `d.equity` / `d.positions` / `d.closed`.
- **Step 4 done (Dhan Analysis):** contract-driven `#page-analysis2` (`a2*` JS / `a2-*` ids, 7 tabs persisted in `localStorage 'tj_a2_tab'`), shown for `pages.analysis === 'v2'`; legacy `initAnalysisCharts`/`initPerfCharts` now only run when the legacy page is the one in use. Built only from open positions + entry signals + equity series; closed-trade sections (loss analysis, behaviour modules, realised attribution) show 'builds as exits are recorded'. **Copy follows dh252 rules** (single exit = Supertrend red, add-on rule, quantity floored to 1 share, no stops/partials/R-multiples) — the mockup's SST-hostile wording was NOT carried over. Hot sectors reuse the engine's top-3 rule. Zerodha keeps the legacy Analysis page.
- **Strategy / Journal / Config tabs removed (2026-11-08, user request).** Nav tabs + workspace page registry entries are gone; the page markup/JS (`#page-strategy`, `#page-journal` + `eq*` Equity-Journal code, `#page-config` + `populateConfigPage`) is left **dormant, unreachable** in index.html (not purged — deleting would also drop the mirrored Equity-Journal logic). Consequences: the Apps Script URL / TRADES column mapping can only be changed in `DEFAULT_CONFIG` now; the Equity Journal (second Apps Script `EQ_SHEET_URL`, FILLS/HOLDINGS sheets) is no longer reachable. **Remaining Google-Sheet dependencies:** (1) the Zerodha workspace's legacy Dashboard/Performance/Analysis read the TRADES sheet via the Apps Script URL in `DEFAULT_CONFIG`; (2) F&O mode and the silent breadth fetch in `refreshData()` read the NSEFO sheet via the same script. The Dhan workspace has **no** Google Sheet dependency (MCP-fed JSON snapshots + yfinance closes + backtester's published files). Startup no longer calls the Apps Script unless the Zerodha workspace is active; `wsSelect('zerodha')` loads it on first use (`window._sheetRequested`).
- **Table controls are uniform (2026-11-09, user).** List tables on Live Trading, Performance, Analysis and Dashboard get search, filter (when a column has 2-8 distinct text values), click-to-sort, CSV export and a row count from the generic `te*` layer in index.html (`teScan`, applied by a MutationObserver; no per-table code). Live Trading blotters already have their own search/filter/export, so they only get click-to-sort (`sortOnly`). Covered Call tables use `ccTbl`. Two-column label/value summary tables are skipped on purpose.

- **AZ pages ignore orders for stocks outside this dashboard (2026-11-09, user):** the AZ 'Orders at next open' table, its count and the refresh-overdue banner skip orders whose stock is neither an AZ entry signal nor one of the dashboard's positions (`dhOwnOrder`, copy flag `hideOtherOrders`); the user's own orders for the old sheet dashboard (for example CYIENT, PIRAMALFIN) stay in `orders_snapshot.json` but are not shown or counted.

- **Strategy scorecard on the dashboard (user, 2026-11-18; ND and AZ).** `#d2-score` / `d2RenderScore(d)` in index.html, under System edge: live max drawdown, current drawdown from peak, return since start, CAGR (shown from 90 days), profit factor, win rate, average winner / loser, average hold, expectancy, capital invested and open positions, each next to the backtest figure and a status chip (On track / Below backtest; stays "Too early" until 90 days of history and 30 closed trades). Backtest references live in `WORKSPACES[id].cfg.bt` (ND: Rs20L, Rs1k + Rs1k ladder, 28.0% CAGR, -15.4% DD, PF 2.01; AZ: Rs30L, Rs20k + Rs5k ladder, flip-today, 20.2% CAGR, -21.3% DD, PF 1.75; both 10 years with 6% on idle cash, from `swing-backtest/RESULTS.md`). Update `cfg.bt` if the sizing rule or the backtest changes. The table has `data-te="off"` so the table-controls layer skips it.
