## UI Changes Made (2026-11-07 session) — Dark "Pro Trading Terminal" Visual Redesign + Rebrand

Scope agreed with user up front: **Dashboard page first, visual elevation only** (no logic/data/card-inventory changes), aesthetic = dense pro trading terminal (Bloomberg/TradingView-like), to be rolled out to other pages later on request. Every change below was verified by actually rendering the live page in a browser (local `python -m http.server` + Playwright MCP screenshots, real data from the real Apps Script) before pushing — not just read from source. This caught several real bugs that code-reading alone would have missed (see below) — keep doing this for future visual passes on this file.

### Design system overhaul (affects every page, since it's all shared CSS)
- New dark-first color tokens in `:root`/`[data-theme="dark"]` — refined, less neon/default-Tailwind: dark bg `#090B10`, surfaces `#10141C`/`#161C26`, accent cobalt `#4C86FF` (dark) / `#2359D6` (light) kept **deliberately distinct from signal colors** (muted green `#2BB583`/red `#E0505F`/amber `#E0A23D` — never reuse these three for brand/UI-accent purposes, they're reserved for profit/loss/caution meaning elsewhere in the app).
- `<html>`'s static `data-theme` attribute changed from `"light"` to `"dark"` — **the app now opens in dark mode by default** for anyone without a saved `tj_theme` in localStorage. `toggleTheme()` itself is unaffected (just flips current attribute) and existing users' saved preference still overrides this.
- New typography: `--font-ui: 'IBM Plex Sans'` (weights 400-800) for all UI text, `--font-mono: 'IBM Plex Mono'` (weights 400-700) for **every numeric value** app-wide (tabular-nums) — hero portfolio value, all KPI grids, `.stat-value`/`.big-metric-value`/`.compare-value`/`.heat-value`/`.expand-value`/`.pnl-pos`/`.pnl-neg`/`.action-pnl`/`.cal-cell-pl`, and all `<td>` cells in every `<table>`. Google Fonts loaded via `<link>` in `<head>`.
- Because most Dashboard hero/KPI numbers are raw inline-styled `<div id="...">` with no shared class (not `.stat-value` etc.), a single consolidated CSS rule listing every such ID by name was added near the end of the `<style>` block (search `DASHBOARD HERO/KPI NUMERALS`) to give them the mono/tabular treatment without touching the HTML — add new Dashboard numeric IDs to that selector list if you add new ones, rather than inlining `font-family` per-element.
- Flatter cards (less/no drop-shadow, crisper 1px borders), tighter radius (12px→10px / 8px→6px), tighter `.page` padding (24→20px) and `.card`/`.card-sm` padding/grid gaps — applies to every page via shared classes.
- Nav wordmark icon fixed: was hardcoded 🌙 regardless of theme; now defaults to ☀️ matching "currently dark, click for light" convention used elsewhere in `toggleTheme()`.
- **Bug found & fixed**: `refreshData()`'s `signal-run-info` nav text was silently rendering literal `"Signals: NaNth undefined, 12:NaN am"` whenever `data.signalRunAt` failed to parse as a date — `new Date(str)` returns `Invalid Date` silently (no exception), so the `try/catch` around it never caught anything. Fixed by explicitly checking `isNaN(sd.getTime())` and throwing, so it falls back to showing the raw string instead. (Turned out the sheet's `AK31` cell currently just contains the literal text `"No"`, not a date — that's a backend/sheet question, not a UI bug; the fix just makes the UI handle whatever the sheet actually contains gracefully.)

### Mobile fixes (Dashboard)
- **Open Book card** (`#dash-openbook-grid` / `#dash-openbook-stats` / `#dash-openbook-lossbuckets` — these IDs were added specifically to make this fixable): the stats-grid + Loss Buckets two-column layout had no mobile breakpoint at all, so on phone widths the Loss Buckets column was getting cut off past the right edge instead of stacking. Added a mobile media-query rule to stack them (stats in 2-col grid, Loss Buckets below with a top divider instead of a side divider).
- The "Open Book" card header label was wrapping into "OPEN"/"BOOK" on two lines whenever the health badge showed a long warning message. Fixed by letting the header row `flex-wrap` instead of squeezing the label (`white-space:nowrap` added to the label).
- Checked for the Re-entry Watchlist table seeming to overflow/cut off on mobile — confirmed this is **intentional, working `overflow-x:auto` horizontal scroll**, not a bug (same swipe-to-scroll pattern already used elsewhere) — don't "fix" this again without checking first.

### Collapsed-by-default changes
- **Dashboard "Long-Held Losers" card**: was always fully expanded whenever any position qualified (`age > 90 days AND plPct < 0`), taking up a lot of vertical space. Now collapsible, collapsed by default, matching the existing `toggleAvgDown()`/`toggleHeatmap()` pattern — new `toggleLongLoss()` function, new `#dash-long-loss-body`/`#dash-long-loss-chevron`/`#dash-long-loss-summary` elements. Summary line shows a count (e.g. "46 positions > 90 days in loss") while collapsed.
- **Performance page full-year P&L Calendar** (`#cal-grid`): had no collapse mechanism at all — the single biggest always-expanded block on that page (12 months of day-cells). Wrapped in the file's existing generic `collapsible-toggle`/`collapsible-body`/`toggleCollapsible(id, btn)` pattern (same one already used right below it for "Show all closed trades") — new `#cal-toggle`/`#cal-body` elements. Also fixed the Dashboard's "Full year ▸" shortcut link (navigates to Performance and `scrollIntoView`s `#cal-grid`) to auto-expand `#cal-body` first — `scrollIntoView` on a `display:none` element is a silent no-op, so without this fix the shortcut would stop working the moment the calendar became collapsible.
- **Checked the Analysis page for an equivalent**: every large section there (Stock Leaderboard, Edge Diagnostics, Unlock Advanced Analytics, F&O's Active Spreads/Top Candidates, etc.) already uses native `<details>` with no `open` attribute — i.e. already collapsed by default. No changes were needed there; don't assume Analysis needs the same fix applied to Dashboard/Performance without checking first (it already does the right thing).

### Rebrand: "Trading Journal" → "VJ TradeIQ"
User picked this name themselves (not one of the suggested options) after being offered several (SST Terminal, Edge Terminal, Breakout Desk, etc.) — "VJ" = the trader's own initials, "TradeIQ" = trading + intelligence. Updated: nav wordmark, `<title>`, password-gate overlay heading, and `copyDashStats()`'s clipboard-copy header text. **Deliberately left unchanged**: the Journal tab's "Equity Trading Journal" heading — that's a specific sub-feature label (the Tradebook-fed FIFO journal), not the app's brand name; don't rename it to match.

### New nav logo mark + favicon (used the `frontend-design` skill end-to-end: brainstorm → stress-test against clichés → build → visually verify → iterate)
- Replaced the 📈 emoji with an original hand-built inline SVG (`.nav-logo-mark` class, 22×22px, `viewBox="0 0 24 24"`): an angular polyline depicting a flat "base" leg breaking into a short steep "breakout" rise, plus a separate horizontal tick crossing the rise near its midpoint to represent the 21-Day-High/GTT threshold being pierced. Pure `stroke="currentColor"`, no fill/gradient — recolors correctly between themes automatically via the existing `--accent` token. Chosen deliberately over a literal chart-line/candlestick/bull/rocket glyph (all rejected as generic finance clichés) and over a curved "VJ" ligature monogram (rejected as too soft for this app's sharp/engineered visual register).
- **Design bug caught during visual verification, not during planning**: the original spec also included a small filled-square "terminal node" at the tip (meant to evoke a GTT order marker). Rendering it at actual size revealed the square overlapping the angled line's own `stroke-linecap="square"` end-cap, producing a spiky/star-shaped artifact — looked broken, not professional. **Dropped the terminal-node square entirely** (from both the nav icon and the favicon variant) after this was caught by zooming into a real screenshot; the line's own flat end-cap plus the crossing tick reads cleanly without it. If anyone ever proposes re-adding a marker/node shape at the tip of this glyph, test it rendered at real size first — overlapping a rotated line-cap with an axis-aligned shape near the same point reliably produces this kind of artifact.
- Restructured the nav markup: the SVG is now a sibling of a new `.nav-logo-text` wrapper span (which contains the old `<span>VJ</span> TradeIQ` text), rather than living inside the old accent-colored `<span>`. On mobile (`≤640px`) the CSS now hides `.nav-logo-text` entirely (both "VJ" and "TradeIQ" collapse together) while the icon persists alone — this is a deliberate change from the old behavior (which only hid "VJ" and had no icon to preserve anyway).
- Added the app's **first-ever favicon** (previously none declared at all — confirmed 404 on `/favicon.ico`) via `<link rel="icon" type="image/svg+xml" href="data:image/svg+xml,...">` in `<head>`, reusing the same glyph geometry but as a self-contained variant: hardcoded accent hex `#4C86FF` (data URIs have no page CSS context, so `currentColor`/CSS vars can't resolve there) plus a solid `#0C0F16` backdrop square behind the glyph (justified here, unlike in the nav itself, because favicons render on uncontrolled/variable tab-chrome backgrounds where a bare thin-stroke glyph can disappear).
