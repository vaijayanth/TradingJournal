## Core operating rules (always apply; the topic rules are indexed below)
- **Stale-refresh alerts (Dhan).** The Dashboard / Live Trading / Covered Call pages show a banner when `/refresh-dhan` is overdue (`dhStaleAlerts` in index.html; `?dhnow=YYYY-MM-DDTHH:MM` simulates an IST time for testing). A project SessionStart hook (`.claude/settings.json`) runs `dhan-live/scripts/stale_check.py` (same rules; `DHAN_NOW=` simulates a time) and, when it prints an alert, tell the user in the first reply and offer to run /refresh-dhan. If that hook is not active in a session, run `python dhan-live/scripts/stale_check.py` yourself at session start. Staleness = signals/holdings older than the last published session, or after-market orders that should have executed at an open with no refresh since (the tradebook is today-only, so a missed fill day loses the fills).

- **Dhan and Zerodha are fully separate (user, 2026-11-09).** They hold overlapping stocks and that is fine; what must never happen is one workspace's code or data changing the other's signals. Backend: `zerodha-live/` imports nothing from `dhan-live/` (helpers vendored in `zerodha-live/scripts/zerodha_common.py`, own `crosscheck_signals.py`, own `data/equity_sectors.json`; the Zerodha refresh reads only `zerodha-live/`). Frontend: each workspace reads only its own `WORKSPACES[id]` URLs, and caches (`WS.data`, `_dhXs`) are keyed by workspace id. When changing a rule for one broker, edit that broker's copy only; there is deliberately no cross-broker marker, exposure view or conflict rule.

- **Workspace display names (user, 2026-11-09):** Dhan is shown as **ND**, Zerodha as **AZ**, ICICI as **DI** everywhere on the pages (switcher, headers, hints, empty states, stale banners). Only display text changed: workspace ids (`dhan` / `zerodha` / `icici`), file paths, function names and the `/refresh-dhan` / `/refresh-zerodha` commands keep the real names. New UI text should use `WORKSPACES[id].label`, not a hardcoded broker name.

- **Refresh reminders and freshness stamps (2026-11-09, user):** (1) while the market is open (Mon-Fri 09:15-15:30 IST) and the last refresh (latest of holdings pull, signals computed, live prices pulled) is more than 60 minutes old, `dhan-live/scripts/stale_check.py` and `zerodha-live/scripts/stale_check.py` (both run by the SessionStart hook in `.claude/settings.json`) print a STALE alert: tell the user in the first reply and offer `/refresh-dhan` or `/refresh-zerodha`. `DHAN_NOW=` / `ZERODHA_NOW=YYYY-MM-DDTHH:MM` simulate an IST time. The same rule shows as a 'Refresh overdue' banner on the pages (`dhStaleAlerts`). (2) Every page's freshness chip (`wsFresh` / `wsPaintFresh`, refreshed every minute) shows the market data date, when the source published it (`source_generated_at`, both engines write it), the last refresh time in IST and how long ago; hover for holdings / signals / live-price times. It turns amber when the market is open and the refresh is over an hour old.
- **Move-candidate nudge (user, 2026-11-16).** `zerodha-live/scripts/move_candidates.py` finds old-sheet positions (the frozen baseline minus those already moved) that are now Supertrend green AND profitable AND in the F&O universe (price = last close in `covered_call_signals.json`, cost = Zerodha holdings average; left out: moved, excluded, `kept_on_sheet`, `data/move_declined.json`, not held now). `--nudge` prints only when there are candidates: it runs in the SessionStart hook (`.claude/settings.json`) and `/refresh-zerodha` step 7 reports it; when it prints, tell the user in the first reply and ask whether to move them. The baseline is a 2026-11-08 snapshot, so a row the user closed on the sheet since then is not known here. 0 candidates today.

- **Stop cool-off and spike flip (user, 2026-11-27, from `swing-backtest/stop_reentry_study.py`).** After a 3x stop fires on a stock (the option ledger tags it `3x stop (gap backstop)`, the engine copies it as `stop_fired`), the SAME direction (a stopped call blocks a new call, a stopped put a new put) is blocked for 5 trading days AND until the Supertrend is at least 6% from flipping: in 6 years of F&O data a 6% adverse 3-day move with no flip turned against the position within 20 days 66% (call) / 59% (put) of the time against 50% / 42% on ordinary days, and waiting 5 days fixed the flip risk but not the 12% tail. The Entry tab shows a red 'Stop fired, cooling off' chip, leaves the stock out of 'Open today' and sets the action to 'Wait'. A fresh flip (5 trading days or fewer) that followed a 6%+ 3-day move in the flip direction is a **spike flip**: the new structure's tail risk is about double (22% vs 12% for a 12% adverse move), so an amber chip says to put the strike 3-4 points further out for a put (about 15% below) and 6-8 for a call (about 18-20% above). `option_entry_tiers.py` applies the same two rules. Information and gating of suggestions only; no order is placed.
