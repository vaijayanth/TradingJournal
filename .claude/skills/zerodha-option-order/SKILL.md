# zerodha-option-order - new option trades for the AZ (Zerodha) account

This places REAL option orders on the user's Zerodha account through the Zerodha MCP. It is the AZ skill for OPENING option positions; `zerodha-gtt-order` protects and cleans up GTTs, `zerodha-order` handles the stock signals. ND (Dhan) keeps its own option placement inside `dhan-superorder` (Part 3); ND and AZ share no code or data, and this skill never imports from `dhan-live/`.

## The rules these orders come from (user, 2026-11-09 and 2026-11-14)
- **What to trade** comes from the Covered Call engine: `zerodha-live/covered_call_signals.json`. Supertrend RED = sell a call. Supertrend GREEN = bull put spread: sell a put and BUY a hedge put 2 listed strikes lower. The RSI override (above 70 = sell call, below 30 = bull put spread) is already inside the signal for AZ. The user chooses WHICH stocks; the structure comes from the engine (the user may name the other structure explicitly, which you say back in the ticket).
- **Which strike:** the listed strike nearest 10% away from the stock price for the current-month expiry, 15% away for a later month (a call above the price, a put below it). The script does this; never pick a strike by hand. An alternative strike only when the user asks, from the quoted neighbours (`--short-strike`).
- **Expiry** is the engine's first expiry at least 30 days away. Expiry week is refused (guardrail P1).
- **Size:** 1-4 lots of the stock's lot size. Default: the number of lots whose net credit is nearest to about Rs2,000 per trade (`--target-credit 2000`), a lot's credit is lumpy, so show the actual credit; the user decides.
- **Stop and target** (used afterwards for the protective GTT): stop = 3x the sold premium, target = 40% of it (the 60% profit rule). Positions are closed 15 days before the stock's results or ex-dividend date: a new option that would still be open inside that window gets a WARNING only, never a block (user, 2026-11-09).
- **The call side is intentionally unhedged** (user): a short call has no hedge leg. Say plainly in the ticket that the loss on a naked short call is unlimited.

## Scope (hard limits)
- Stock options on NFO, product NRML, regular LIMIT orders. Never index options, futures, equity, GTT deletion, or any stock outside `zerodha-live/data/fno_universe.json` (minus `excluded_symbols.json`: BSE, BEL, RECLTD). Never market orders. **The market must be OPEN (Mon-Fri 09:15-15:30 IST)**; if it is closed, say so and stop (option quotes and fills only make sense live).
- Maximum **4 stocks per instruction**; a stock the user names that is not in the list is refused with the reason.
- Numbers come only from `python zerodha-live/scripts/build_option_ticket.py`: strike, lot, quantity, hedge, limit prices (the middle of the live bid-ask, rounded to the 0.05 tick), credit, maximum loss. Never invent or change a number; the user may override a limit price only with `--short-limit` / `--hedge-limit`, which re-prints the ticket.
- One explicit confirmation per stock's ticket (hedge + short together), for the exact orders shown. Any change = show the ticket again and re-confirm. Never act on an implied or earlier "yes".
- Never retry a rejected order; never modify, cancel or chase a price without being asked; never place while a refresh is running.
- Refuse when `zerodha-live/data/trading_halt.json` has `halt: true` or guardrail H1/X1 is raised. The F5 price-data block and the other equity-signal blocks do NOT stop option trades (user, 2026-11-09). Never flip the kill switch unless the user asks.

## Steps
1. **Login and funds.** `mcp__claude_ai_Zerodha_Mcp__portfolio` `mode: "margins"`; if it asks to log in, call the session login tool, show the link and wait. Note equity cash, collateral and utilised. Zerodha has no per-order margin calculator in this connector: say plainly that the exact margin is unknown until Zerodha accepts or rejects the order, that a bull put spread needs far less than a naked call, and show the cash and collateral as the only guide.
2. **Market open and fresh state.** Check the time (IST). Pull `portfolio` `mode: "positions"` (large; saved to a file) -> `python zerodha-live/scripts/cc_positions.py <file>`, then `python zerodha-live/scripts/compute_covered_call.py` so the list reflects what is open right now. If the last `/refresh-zerodha` is more than a session old, tell the user to refresh first.
3. **List.** `python zerodha-live/scripts/build_option_ticket.py list` (add `--max 40` or `--symbols A,B` if the user wants more or specific stocks). Print the FULL numbered table every time: number, stock, structure, price, RSI, colour, flip age, expiry, lot, status (ENTER = nothing open; FLIP = an opposite structure is open, which this skill does NOT close: tell the user to close it in the app first, or to accept having both), and any results/ex-dividend warning. Ask once: "Which stocks (numbers or names, up to 4)?" Echo the choice back. Never default to everything. Refuse anything not in the list.
4. **For each chosen stock (one at a time):**
   a. `python zerodha-live/scripts/build_option_ticket.py plan --symbol <SYM> [--structure ...]`: it prints the listed strike it picked and `QUOTE_INSTRUMENTS=[...]`. Get the live stock price with `market` `mode: "ltp"` `["NSE:<SYM>"]`.
   b. Quote those instruments with `market` `mode: "quote"` and save the RAW JSON verbatim to `zerodha-live/data/cc_raw/option_quotes_<SYM>_<EXPIRY>.json` (the script refuses a quote file that was not saved today).
   c. `python zerodha-live/scripts/build_option_ticket.py build --symbol <SYM> --quotes <that file> --spot <live price> --target-credit 2000` (or `--lots N`). Read the `TICKET_JSON=` line.
5. **Ticket + confirmation (per stock).** Show: stock, structure, expiry, live price, the short leg (strike, % from the price, bid / ask / last, open interest in lots, volume, circuit limits), the hedge leg for a spread, every WARNING the script printed (wide spread, thin OI, no bid, no trades, stop above the circuit limit, results/ex-dividend window), the nearest liquid alternative if one was offered, lots and quantity, **net credit in rupees, the maximum loss (spread) or "unlimited, naked call"**, the cash and collateral from step 1, the exact orders in sequence (hedge BUY then short SELL: contract, quantity, LIMIT price, NRML), and the later protective GTT levels (stop, target). Add the plain note: a limit order at the middle of the spread may not fill; nothing is chased. Ask the user to reply "yes, place these" and wait. If a WARNING makes a leg doubtful (no bid, very wide spread), recommend the alternative or skipping, but never decide for the user.
6. **Place** with `mcp__claude_ai_Zerodha_Mcp__orders` `mode: "place"`: `variety: "regular"`, `exchange: "NFO"`, `tradingsymbol`, `transaction_type`, `quantity` (units, lots x lot size), `product: "NRML"`, `order_type: "LIMIT"`, `price`, `validity: "DAY"`, `tag: "AZOPT"`.
   - **Spread: hedge BUY first.** Place it, then check `orders` `mode: "list"` until it is COMPLETE (filled). Only then place the short SELL. If the hedge is still open after a short wait, STOP, tell the user, and do not place the short (the short must never exist without its hedge). The user decides whether to modify the hedge price or cancel it.
   - **Call:** the short SELL alone.
   - If the exchange rejects a price (tick size, circuit limit, margin), STOP, report the message verbatim, show a corrected price for a fresh "yes"; never guess. Stop at the first rejection; never retry.
   - If Zerodha returns an approval link instead of placing (browser approval), share it and wait; do not repeat the order.
7. **Verify.** `orders` `mode: "list"`: for every order of this stock confirm side, quantity, price, tag and status (COMPLETE / OPEN / pending). Report order id and status per leg in a table. A pending order is not a fill: never say it filled. Option orders are NOT written into `orders_snapshot.json` (the AZ pages track the stock orders of the dashboard only); positions come from the next `/refresh-zerodha` (`get_positions` -> `cc_positions.py`).
8. **Protective GTT (a separate, separately confirmed step, only for a SHORT that is now filled).** Re-pull `portfolio` `positions` -> `cc_positions.py` and `gtt` `mode: "list"` -> `cc_gtts.py`, then `python zerodha-live/scripts/build_gtt_tickets.py`. It lists the short legs that still have no active buy-back GTT (the new short should be there; if its premium is already at or past the 3x stop it says "NOT TICKETED: close it now"). Show the numbered GTT list for the new leg only (the same two-leg ticket zerodha-gtt-order builds: upper trigger = stop, lower trigger = profit target, limits = trigger + 3% rounded up to the 0.05 tick), the cost at the stop limit, and "Protective GTT: it buys back your short option if the premium reaches a trigger. Nothing is bought unless one triggers." Ask for "yes, place these" and wait; then `mcp__claude_ai_Zerodha_Mcp__gtt` `mode: "place"` exactly as `zerodha-gtt-order` Part 2 step 4 (place one, verify with `gtt` `mode: "list"`). If the user declines or the short is not filled, say the leg is unprotected and that `/zerodha-gtt-order` will list it. The GTT scan and alerts are refreshed by `/refresh-zerodha` or `/zerodha-gtt-order`.
9. **Repeat** steps 4-8 for the next stock. After the last: summary per stock (placed / filled / pending / failed with the verbatim error / skipped / GTT placed or not).

## After the run - tell the user the next skill
- If any order is still pending (a limit that did not fill), say so and that nothing is chased.
- Next: `/zerodha-gtt-order` if any new short has no GTT yet; after the close or the next morning `/refresh-zerodha` so the Covered Call page, P&L and alerts pick up the new positions.

## Reporting
Plain: placed / status / still pending / failed (verbatim error). Never call a pending order filled, and never say a GTT is active unless `gtt` list shows it.
