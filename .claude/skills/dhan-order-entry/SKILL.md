# dhan-order-entry — real-money after-market BUY orders for dh252 signals

This skill places REAL orders on the user's Dhan account through the Dhan MCP. The user's routine: signals are computed after the close and orders go in as after-market orders (AMO) for the NEXT trading day. Zerodha will get its own `zerodha-order-entry` with different logic; keep Dhan specifics here.

## Scope (hard limits)
- Stocks only. Never options, futures, ETFs, or the option-hedge / investment portfolio.
- Only symbols that appear in the current signal file (`dhan-live/dhan_live_signals.json`) as `entries` (kind `entry`) or `addons` (kind `addon`). Quantity is whatever `build_order_ticket.py` says - never a number the user or you make up. If the user names a stock with no signal, refuse.
- AFTER-MARKET (AMO) LIMIT orders only, CNC (delivery). Never market orders. Never during market hours (see step 3).
- One explicit user confirmation for the exact batch shown. Any change (symbol, qty, price) = show the ticket again and re-confirm. Never place anything on an implied or earlier "yes".
- Signals flagged by the cross-check (`dhan-live/data/signal_crosscheck.json`, recomputed from complete Yahoo history) are BLOCKED: `build_order_ticket.py` lists them as BLOCKED and will not include them. Never work around it; `--override SYMBOL` exists but only the user may ask for it, naming the stock, after you have shown the flag reason.
- Never retry a rejected/failed order, never modify or cancel without being asked, never place orders while a refresh is running.

## Steps
1. **One-shot pick.** EVERY time this skill is invoked, re-run the script and print the FULL numbered table again, all rows, even if the same list was shown earlier in the conversation - never write "same as before" or point back at an earlier message. Run `python dhan-live/scripts/build_order_ticket.py buy` (after steps 2-3 below) and print its numbered list to the user VERBATIM as a table: number, stock, qty, reference price, est. value, and whether it is an `entry` or an `addon` signal (entries and add-ons are in one list). Directly under the table, ALWAYS show a **capital check** (get the figures from `portfolio_agent_tool` action `funds` and `dhan-live/dhan_live_signals.json`): Dhan available balance (cash + collateral margin), withdrawable cash, collateral, utilised; the dh252 starting capital (`capital_base`, fixed 20,00,000), dh252 invested now (sum of open positions' invested) and the undeployed remainder; and the total est. value of ALL listed signals (entries and add-ons separately, +2% worst case for the limit) as a % of available balance, of withdrawable cash and of the dh252 base. Say plainly that most of the available balance is collateral, not cash. Then ask once: "Reply with the numbers to place - e.g. `3,7,25-27` - or `all addons`, `all entries`." Translate their reply into numbers yourself and echo it back. Never default to everything; if the reply is unclear, ask again. The user may also name stocks ("CYIENT, STOVEKRAFT"): map them to numbers, and refuse any stock not in the list.
2. **Fresh data - after the close.** Signals must be the day's final ones. The backtester's "Daily OHLC Update" publishes after the close (around 16:00 IST; run it manually from GitHub Actions if needed), then run `/refresh-dhan`. `build_order_ticket.py` refuses data older than 3 days, but you must also check `market_data_date` is the session that just ended.
3. **Market must be closed.** NSE equity trades Mon-Fri 09:15-15:30 IST (plus announced special sessions). If the market is OPEN now, stop: tell the user to run this after the close. (If it is a weekend/holiday or after 15:30 IST, continue in AMO mode.)
4. **Tickets.** `python dhan-live/scripts/build_order_ticket.py buy --pick <numbers>` (same list, so the numbers match) -> read the `TICKETS_JSON=` line and the printed total.
5. **Day's range + guard.** For each ticket call `market_data_agent_tool` action `ohlc` payload `{"NSE_EQ": [<securityId>]}` (after the close it returns the finished session as `O/H/L/C`). Get `securityId` from `search_agent_tool` action `search` payload `{"query": "<SYMBOL>-EQ"}` (the NSE `EQUITY` row). If the close differs from the ticket's `ref_price` by more than 3%, stop and ask.
6. **Limit price = the signal day's HIGH, capped at close + 2%** (the user's rule). BUY limit = min(that session's high from step 5, close x 1.02), with the 2% cap rounded DOWN to the 0.05 tick so it never exceeds 2%. Show close, high, cap and the resulting limit side by side, and mark the rows where the cap applied. Say plainly that a limit order fills at the open price whenever the stock opens at or below it, so you normally pay the opening price (not the limit); the cost is that on a gap-up the order can fill up to the limit, and if it opens above the limit it will not fill. The user may override the price.
7. **Funds.** `margin_agent_tool` action `single` with `{"exchangeSegment":"NSE_EQ","transactionType":"BUY","quantity":<q>,"productType":"CNC","securityId":"<id>","price":<limit>}`; (price = the high-based limit; this is the worst-case cash needed) compare Total Margin with Available Balance for the whole batch. (Its "Insufficient Balance" line has shown nonsense - trust Available Balance vs Total Margin.) Stop if funds are short.
8. **Ticket + confirmation.** Show a table: symbol, side, qty, limit, est. value, reason, total, plus the batch total next to Dhan's available balance and withdrawable cash (the step 1 capital check, recomputed for the picked batch), and the line "AFTER-MARKET order for the next trading day". Ask the user to reply "yes, place these" and wait. Nothing is placed before that.
9. **Place.** For each ticket in order, `trading_agent_tool` action `place` with the margin call's field names plus `"orderType":"LIMIT"`, `"validity":"DAY"`, `"afterMarketOrder":true`, `"amoTime":"OPEN"` (Dhan's AMO options are PRE_OPEN / OPEN / OPEN_30 / OPEN_60; use OPEN unless the user says otherwise). These field names follow Dhan's API and have not yet been confirmed through this MCP: if the tool reports a validation error, STOP and report it verbatim - do not guess other fields. Stop at the first rejection and report which orders did and did not go through.
10. **Verify the order is accepted.** `orderbook_agent_tool` to read each order's status (AMO orders sit as pending/"after market" until the next session). Report order id and status per stock. Nothing has filled yet - do not say it has.
11. **Record the fills NEXT trading day.** The MCP tradebook is today-only, so on the next trading day (after the open) run `/refresh-dhan`: its tradebook step records the fills with `append_fills.py`. Orders that did not fill (limit not reached) stay out of the trade log. Remind the user of this at the end of the placement.

## Reporting
Be plain: what was placed (as AMO), its status, what is still pending, what failed. Never describe a pending AMO as filled.
